# Contributing to SignalForge

## Development Workflow

1. Pull the latest `main` branch.
2. Create a feature branch.
3. Make focused changes.
4. Test locally.
5. Commit using the project's commit conventions.
6. Push the branch.
7. Open a Pull Request.
8. Merge after review.

## Branch Naming

Use:

- `feature/...`
- `fix/...`
- `ml/...`
- `backend/...`
- `frontend/...`
- `database/...`
- `docs/...`

Examples:

- `feature/signal-dashboard`
- `ml/growth-features`
- `backend/signal-api`
- `database/posts-schema`

## Commit Convention

Use:

- `feat:` — new functionality
- `fix:` — bug fix
- `ml:` — machine learning changes
- `data:` — data pipeline changes
- `backend:` — backend changes
- `frontend:` — frontend changes
- `db:` — database changes
- `docs:` — documentation
- `test:` — tests
- `chore:` — configuration/tooling

Example:

```text
ml: add signal growth feature
